## 1. 设计概念：账簿 / 校样

这个产品的核心不是"看进度"，而是**当有人问「凭什么他 12 分」时，能当场翻出账**。
所以界面不往仪表盘走，往两样东西走：

- **账簿（ledger）**：每一条都有编号、有出处、有算式，数字右对齐、用等宽数字。
- **校样（galley proof）**：要求是从文件里"读"出来的，所以要能对到原页原文，像编辑对着校样划红。

由此推出三条硬规则：

1. **数字必须有出处** —— 每个分数旁边都有 `8.0 × 100% × 100% = 8.0` 这样的算式行，点进去能追到条目。
2. **状态用印章，不用颜色块** —— 已确认/待确认是方框章（`bg_stamp`），因为"核对过"是个动作留下的痕迹。
3. **分隔靠线，不靠卡片阴影** —— 1dp 细线 + 24dp 页边，没有圆角、没有 elevation。

## 2. 设计语言

### 2.1 色彩（靛—瓷）

| Token | 值 | 用在哪 |
|---|---|---|
| `paper` | `#F1F3F5` | 页面底色（冷白瓷） |
| `sheet` | `#FFFFFF` | 需要"抬起来"的块：证据、弹层、选中态文字 |
| `ink` | `#0A1F3D` | 正文、数字、标题（靛黑） |
| `muted` | `#5F6B78` | 辅助说明、单位、时间 |
| `line` | `#D8DEE5` | 1dp 分隔线、未选中轨道 |
| `accent` | `#315D93` | 主色：选中、可点、印章 |
| `accent_wash` | `#E4EAF2` | 待确认横条、头像底、选中块浅底 |
| `ochre` | `#B4472E` | **只**用于偏差/未决/解析失败 |
| `ochre_wash` | `#F3E4DF` | 出错块底色 |
| `ochre_veil` | `#2EB4472E` | 证据高亮（18% 透明，保证原文可读） |

规则：**赭色是警报色，不许拿来装饰**。全篇只有 4 处赭色：待确认章、解析失败、未决、证据高亮。

### 2.2 字体

| 角色 | 字体 | 字号 | 说明 |
|---|---|---|---|
| 页面标题 | `serif`（Noto Serif CJK） | 28–30sp | 中文衬线在设备上真实可用 |
| 大数字 | `serif` + `tnum` | 34–44sp | 分数、总额、条目编号 |
| 小标题 | `sans-serif-medium` | 15–20sp | 条目标题、成员名 |
| 正文/表单 | `sans-serif` | 13–14sp | 行高 1.4–1.5 |
| 数据 | `sans-serif` + `tnum` | 13sp | 算式行、百分比 |
| 微标签 | `sans-serif` | 10sp，`letterSpacing 0.12` | `分摊`、`要求对照`、`快照` |

`tnum`（等宽数字）是硬要求：账本里的 1 和 8 必须同宽，否则右对齐的数字会跳。

### 2.3 网格

- 页边 24dp，栅格按 4dp 基线。
- 条目行最小 72dp：左 40dp 是编号槽（`01`–`12`），右 72dp 是分数/状态槽。
- 圆角 0，阴影 0；层次只靠底色 `paper`/`sheet` 与 1dp 线。

```
### 3.1 多项目：一个学生同时在几门课里
```

- **项目库没有 tab 栏**：它是账号层，不是第 5 个 tab。点项目才"进入"，返回键从任意 tab 的根页回到项目库（再按才退出），所以"我现在在哪个项目里"始终有答案。
- **按课程归档**：课程是分组标题（右侧标学期），同一门课可以有多组；一行显示组号 · 人数 · 计划版本，右侧是待确认数或"我创建"。

| 位置 | 图标 | 动作 |
|---|---|---|
| 左 | 回到项目库的左箭头（和二级页返回栏同一个 `ic_back`） | 退出当前项目，回项目库 |
| 右（组号左边） | 齿轮 `ic_gear`（2.0 描边、8 齿、中空环，22dp；12 点方向正对一个齿） | 打开应用设置（名字 / 字号） |

- 左箭头只在项目内出现；项目库是根页，没有它。
- 原来标题旁那个"⌄"已经去掉——有了明确的左箭头，这个箭头本身就是唯一的"离开项目"入口，两个控件指向同一件事反而让人犹豫。
- 齿轮在二级页的返回栏里也有一份（`待确认` 章右边），所以"设置"在任何页面都是同一个位置、同一个图标，不再用文字按钮。

### 3.3 三个状态（不止正常态）

| 状态 | 触发 | 表现 |
|---|---|---|
| 列表空 | 点某一阶段刻度后该阶段无条目 | 该段只留标题 + `没有…的工作项` |
| 解析失败 | 材料页点 `小组计划.docx` | 赭色块 + `无法解析这份文件` + `重试解析 → 仍然失败 · 请转成 PDF` |
| 零分结算 | `total <= 0`（代码路径已留） | 结算单换成空态块，不给 0.0 大数字 |

## 4. 界面逐个说

前六节是项目内的主流程（①–⑥），⑦–⑩ 是新增的账号层与项目管理。

### ① 板（主屏）

结构自上而下：课程/组号 → `小组看板` 30sp + `计划 v3` → 4 段刻度条 → 成员栏 → `待你确认 · 3` 条 → 分组列表。

- **刻度条不是进度条**：四格分别显示 `1 / 1 / 3 / 7`，每格上方 2dp 细线，点一下就是筛选（再点取消），选中的线变主色并下沉到格底——它同时是导航和过滤器。
- **成员栏**用方形头像（不是圆形）+ 百分比，百分比 = 个人积分 ÷ 小组总分，随确认实时变化。
- **待你确认条**是唯一允许"抢注意力"的元素：3dp 左侧主色条 + 浅底，点它直达第一个待办。
- 条目行：编号槽 `08`、标题、`李文豪 · 8 分 · 独担`、右侧分数（未确认显示 `—`，用线色）+ 状态。待确认的状态包在方框章里。

### ② 工作项详情

- 顶部 40sp 编号 `08` 是从列表行**共享元素**放大过来的（见 §7）。
- 右上角只有三种可能：`已确认`（主色章）/ `待确认`（赭色章）/ 没有章（进行中、待开始）——**章只代表"核对过"**，所以草稿态不盖章。
- 分摊条 6dp：自己是主色，其他人 `ink_40`，下面一行图例。
- 要求对照：左边 56dp 微标签（形式/位置/截止），右边值；与提交物不符时整行转赭色并加 `与要求不符`。
- 成果证据：文件/链接/文字 + 3 格证据强度 + `打开链接并定位`。
- 计分块：`计入李文豪的 4.0 分` + `8.0 × 50% × 100% = 4.0`；未确认时算式后加 `· 尚未确认`。
- 主 CTA 按状态给四种文案：`确认完成` / `已提交 · 等待 王舜祺 确认`（禁用）/ `提交成果` / `查看结算单`。

### ③ 提交成果

- 三格 `文件 / 链接 / 文字`，副标签分别是 `上传附件 / 粘贴地址 / 直接写`，切换时 200ms 淡入。
- **页内选文件**（不用系统弹窗）：点虚线框展开白色面板，三行示例文件，行间细线；选中后虚线框收成文件行 `汇报PPT_v3.pptx / 4.2 MB · 修改于 …`，可移除。
- 提交后回到详情：证据块出现、状态变待确认、CTA 变成等待文案。

### ④ 完成确认

这一页只做一件事：**让你清楚这一下会改什么**。

- 三格 0/50/100，滑块是 180ms 弹簧（damping 0.85），选中格文字转白。
- 大数字 `4.0` 用 600ms 数字滚动，算式 `8.0 × 50% = 4.0` 实时跟着变。
- 新增 `这一格确认后` 三条：`李文豪 的积分 4.0 → 8.0`、`小组总分 67.0 → 71.0`、`待确认 3 项 → 2 项`；没变化的行显示 `4.0 · 不变`。
- 页脚固定：`确认 · 50%` + `确认人为非提交人 · 结果立即写入结算单`。

### ⑤ 结算单

- `71.0 分` + `已确认 8 / 12` + `12 个工作项 · 总分 100 分 · 已计入 71.0%`（这是确认 08 之后的样子；初始为 `67.0 分 / 已确认 7 / 12`）。
- 构成条 8dp：四段同色不同透明度（0.95 / 0.66 / 0.46 / 0.28），按占比切分。
- 成员四行**固定顺序，不排序**——产品不允许排名，所以列表顺序不随分数变化，避免暗示。
- 每行：名字（自己带 `· 你`）、`18.8`、`26.5%`、`3 / 4 项已确认`、3dp 占比条。
- 待确认提示块（赭色浅底）：`2 项待确认 · 2 项等你` → `去处理`。
- 底部写明算法：`个人积分 = Σ (基础分 × 完成度 × 分摊)`、`占比 = 个人积分 ÷ 小组总分`，并注明 `规则 v1.2 · 占比不等同于课程成绩`。

### ⑥ 成员明细

- 逐条算式，40ms 交错出现：`01 需求梳理与竞品调研 8.0 / 10.0 × 100% × 80% = 8.0`。
- 未确认的条目单独一段 `尚未计入`：分数位显示 `—`，下面赭色写 `待确认 · 若 100% 则 6.0`。
- 页脚：`快照 11-14 21:06 · 规则 v1.2` + `这一页只陈述计算过程，不做排名，也不给建议等级`。

### ⑦ 项目库（账号层）

- 抬头只写身份与规模：`何嘉俊 · 2026 秋` / `2 门课程`，标题 `项目库` 下面一行 `4 个项目 · 5 项待确认`。
- 邀请条在最上面：`邀请 · 待处理`（赭色）、项目名、`周楚涵 邀请你 · SOFT3001 · 5 人`、`查看邀请 ›`。一条就够，多了反而像收件箱。
- 课程做分组标题（`CS4001 · 人机交互` + 细线 + `2026 秋`），项目行走 `row_project`：名称 16sp、`GROUP 16 · 4 人 · 计划 v3`、右侧待确认数（赭色）或 `我创建`。
- 底部两个动作：`创建项目`（实心）/ `加入项目`（描边）；页脚 `项目按课程归档 · 同一门课可以有多组`。

### ⑧ 创建项目

一页填完，不分步：课程 chips（含 `+ 新课程`，展开后填代码/名称）→ 项目名称（选课后自动补 `人机交互小组作业`）→ 工作项模板（空白 / 按周 4×25% / 按交付物 20-30-30-20）→ 总分（默认 100）→ `加入需要我确认`（默认关）。底部 `创建并进入`，创建后你就是发起人。

### ⑨ 加入项目

`输码 → 预览 → 加入`：

- 6 位码用衬线 26sp + 字距铺开，像输入密码；下面一行 `用 周楚涵 的邀请码 R3F8K2 填入 ›` 可以从收件箱直接带过来。
- 预览卡：项目名、`SOFT3001 · 软件工程 · G07`、四行事实（发起人 / 成员 / 已建工作项 / 加入方式），底部只有一个 `加入项目`。
- 三种失败各有文案：`没有找到这个邀请码`、`这个邀请码已过期，请让发起人重新生成`、`你已经在「X」里了`（并把 CTA 换成 `打开项目`）。

### ⑩ 项目设置

- 抬头写清角色：`CS4001 · 人机交互 · GROUP 16 · 创建者`。
- 创建者：邀请码 `K 7 M 2 Q 4` + `复制` / `重新生成`（旧码立即失效）+ `加入需要我确认` 开关 + 成员行 `移除`。
- 成员：邀请码与开关整段隐藏，只留一句 `邀请码与「是否需确认」由发起人 陈实 管理；你只看到成员和已有的确认。`
- 两个出口：`切换项目`（回项目库）、`退出项目`（赭色，退出后从项目库移除，已确认记录留在其他成员那里）。

### ⑪ 应用设置（每个页面都有）


- 入口：五个 tab 页在抬头右上角（`设置`，就在 `GROUP 16` / `2 门课程` 左边），所有二级页在返回栏右侧（`待确认` 章右边）。点开是从底部升起的设置面板，压暗 0.35，240ms 上浮。
- 两个设置：**你的名字**（改完立刻反映到成员栏、结算单、`确认于` 记录）与 **字号**（大 1.15× / 中 1.00× / 小 0.88×，中档就是本文所有尺寸）。
- 名字走 `Demo.renameViewer`（同一个 `Member` 实例，所以全应用一起变）；字号走 `Configuration.fontScale`，保存后只有真正变了档才 `recreate()`，不会闪烁。
- 面板底部注明 `演示环境：设置只保存在这台设备上`——不假装有云端账号。

### ⑫ 新建与编辑工作项

**新建**：板页抬头右侧的 `+`（齿轮左边）。整页表单，不弹窗，因为字段多；默认值已经填好，多数情况只改标题就能保存。

- 字段：标题 / 负责人（成员 chips，默认自己）/ 分值（默认 5，下面一行 `已分配 100 / 100 · 还剩 0`）/ 阶段（待开始、进行中）/ 分摊（每人一行百分比，合计必须 100）/ 交付形式（文件、链接、文字）/ 位置 / 截止 / 说明。
- 编号自动取「当前最大号 + 1」，保存后按阶段插进板的分组，组内按编号排序；**编号不回收**，删掉的号会空着。
- 分值提示只陈述事实：`计划 100 分 · 含这一项共 105 分，结算单按实际总量算`，不报红——计划不是上限。
- 保存后 `Motion.stamp` 一下 CTA 就回板，新行以 40ms 递进的列表动画出现。

**编辑**：详情页返回栏右侧的 `编辑`（在状态章和齿轮之间）。只在「发起人或负责人」且这一项未被确认时出现。

| 状态 | 能改 | 界面表现 |
|---|---|---|
| 待开始 / 进行中 | 全部字段 | 正常表单 |
| 待确认 | 标题、位置、截止、说明 | 分值/分摊/负责人置灰，页脚改 `确认后再改分数，请走修正申请` |
| 已完成 | 只读 | CTA 变 `已确认 · 不可修改`，整页置灰 |

- 改动记录：只记真正变化的字段（`标题`/`负责人`/`分值`/`分摊`/`阶段`/`截止`/`交付形式`/`位置`/`说明`），每条 `MM-dd HH:mm · 谁 · 字段 旧 → 新`；详情页底部出现 `改动记录 N 条 ›` 可展开，标题下方 meta 也带一句 `上次改动 wsq 11-15 13:22`。
- 删除只对「待开始/进行中 + 没有提交证据」可见，确认文案明确说 `删除后编号不回填，08 会空着`。
- 权限：p1 你是发起人，能改全部；p2/p3 你是成员，改别人名下且未确认的项会被挡住——正好演示只读态。

## 6. 计算与文案

### 6.1 算法（代码里就是这么算的）

```
单条得分   = 基础分 × 完成度(0/50/100%) × 个人分摊
个人积分   = Σ 单条得分
小组总分   = Σ 已确认条目的单条得分
占比       = 个人积分 ÷ 小组总分
```

演示数据：12 条共 100 分；确认 w08 到 100% 后小组总分为 `67.0 → 71.0`，占比从 `28.1/26.9/19.4/25.7` 变成 `26.5/25.4/18.3/29.9`。

### 6.2 文案原则

| 不说 | 说 |
|---|---|
| 你贡献了 12 分 | `12.0 × 100% × 60% = 7.2`，并标出处 |
| 排名第 2 | 只给分数与占比，不排序 |
| 建议给 A | 只陈述过程，`不给建议等级` |
| 提交成功 | `提交给 王舜祺 确认`（下一个人的动作） |

## 8. 实现与工程说明

- **技术栈**：Kotlin + 传统 View（`AppCompatActivity` + `Fragment`），Material 1.10、ConstraintLayout、DynamicAnimation（弹簧）、Transition（容器变换）。
- **为什么不用 Compose**：这台机器离线，Gradle 缓存里没有 `androidx.compose.*`，`material3` 也拉不下来；强行加依赖只会构建失败。所以用 View 体系手写，反而更贴"版面"这条设计线。
- **为什么用 `findViewById` 而不是 ViewBinding**：缓存里缺 `androidx.databinding:viewbinding:9.5.1` 运行时，离线无法解析。改为手写 `findViewById`，无额外依赖。
- **构建**：`.\gradlew.bat --offline :app:assembleDebug`（AGP 9.5.1 自带 Kotlin 编译，无需 kotlin 插件；需要 JDK 25，本机用 Android Studio 自带 JBR）。
- **安装**：`adb install -r app\build\outputs\apk\debug\app-debug.apk`，`adb shell am start -n com.example.mycoursepractice/.MainActivity`。
- **代码结构**：
  ```
  MainActivity.kt            外框：容器 + 4 tab + 返回栈联动
  ui/Ui.kt                   尺寸/字体/颜色/细线/数字格式化扩展
  ui/Motion.kt               时长与曲线常量、rise/stagger/stamp/settle
  ui/Nav.kt                  push/popBack、tab 显隐、共享元素
  ui/widget/SegmentBar.kt    方角分格控件（弹簧滑块）
  data/Demo.kt               12 条工作项 + 计分/占比/待确认查询
  screens/*Fragment.kt       板、详情、提交、确认、结算、成员、收件箱、材料、要求、证据、修正、计划
  ```
- **演示数据只在内存**：`Demo` 是单例对象，任何确认/提交都会改它并 `bump()` 版本号，返回上一页时自动重绑；重启进程即回到初始状态。

## 10. 已知限制

1. 全部为演示数据，无账号、无后端、无持久化；杀进程即重置（包括新建的项目和已接受的邀请）。
2. 证据页是**一张静态文件图** + 覆盖框，不解析真实 PDF；这是刻意选择（见 §5）。
3. 文件选择是页内示例列表，不申请存储权限。
4. 计划确认只改文案与印章，不回写工作项（真实产品里应生成 v4 的分摊）。
5. 零分结算单的空态代码存在，但演示数据不会走到。
6. 多项目是本地状态：邀请码只认内置的 `R3F8K2`，`X9T2W5` 用来演示过期；不能真的发给别人。
