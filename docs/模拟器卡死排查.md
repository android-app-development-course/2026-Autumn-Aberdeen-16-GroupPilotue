# 启动模拟器把电脑拖死 — 排查与修复

## 症状

有时点开 `medium_phone`（Android Studio 里点 ▶，或命令行 `emulator -avd medium_phone`），电脑会卡死：鼠标能动但窗口全白/无响应，或者直接黑屏重启，只能长按电源键。

## 证据（来自 Windows 事件日志与系统计数）

**异常关机 / 蓝屏**

| 时间 | 事件 | 说明 |
|---|---|---|
| 2026-11-14 10:59 | Kernel-Power 41 | 非正常关机 |
| 2026-11-14 17:28 | BugCheck 1001 | `0x0000004E` (PFN_LIST_CORRUPT)，dump 存于 `C:\Windows\Minidump\111426-13859-01.dmp` |
| 2026-11-15 11:46 | Kernel-Power 41 | 非正常关机 |
| 2026-11-15 11:51 | Kernel-Power 41 | 非正常关机 |
| 2026-11-15 12:41 | EventLog 6008 | 上次关机是意外关机（18:44 开机时补记） |

两次都在使用模拟器的时间段内（11-14 17:2x 正在跑截图，11-15 11:4x–12:4x 正在开模拟器）。

**资源水位**

| 项 | 数值 |
|---|---|
| 物理内存 | 15.6 GB |
| 模拟器启动前「可用」内存 | 0.4 – 1.4 GB（Studio 3.6 GB + Edge 约 2 GB + Steam 0.4 GB + node 0.9 GB + Defender 0.4 GB） |
| 提交上限 | 39.6 GB（物理 15.6 + 页面文件 24 GB） |
| C 盘剩余 | 33.6 GB |
| quickboot 快照 | `snapshots` 目录 **2.5 GB**，`saveOnExit = true` |
| 模拟器内存 | qemu 实际拿到 **2560 MB**（config 里写 2048） |

## 根因判断

1. **主因：16 GB 内存被吃满后，模拟器再要 2–2.5 GB，Windows 只能疯狂换页。**
   可用内存只剩几百 MB 时，整机进入换页风暴：磁盘 100% 占用、窗口全白、看起来"死了"。这正是 11-15 那几次没有蓝屏、只有 Kernel-Power 41 的情形。
2. **加剧因素：quickboot 快照。** 每次退出把 2.5 GB 内存镜像写回磁盘、每次启动读回；磁盘本来就只剩 33 GB，写回时又是换页最严重的时候。11-14 17:28 的蓝屏就发生在快照保存/恢复前后。
3. **`0x4E PFN_LIST_CORRUPT` 单独看更像是内存页帧表被破坏**，典型原因是内存条不稳或驱动 bug。它只出现过一次，不能排除硬件；需要在修完内存压力后跑一次 Windows 内存诊断确认。

VBS/Hyper-V 已关闭、AEHD 2.2 正常运行、NVIDIA 驱动无 TDR(4101) 记录 —— 这几项不是主因。

## 已做的修改

1. **AVD 改为只冷启动**（`...\MyApplication2\.android_user\avd\medium_phone.avd\config.ini`）：
   ```ini
   fastboot.forceColdBoot=yes
   fastboot.forceFastBoot=no
   ```
   不再读写快照，避免 2.5 GB 的读写尖峰。
2. **删除旧快照与残留锁**：`snapshots\` 整个清空（回收 2.5 GB，C 盘剩余 33.6 → 36.1 GB），清掉 `hardware-qemu.ini.lock`、`multiinstance.lock`。
3. **新增低内存启动脚本** `tools/start-emulator.ps1`（配套 `tools/start-emulator.cmd` 可双击）：
   - 启动前检查可用内存与 C 盘空间，不够就明确报警；
   - 内存偏少时自动把模拟器内存降到 1536–2048 MB（不再硬要 2.5 GB）；
   - 清掉上次崩溃残留的 `qemu-system-x86_64` 与 lock；
   - 用 `-no-snapshot -memory <自适应> -cores 4` 冷启动，并等到 `sys.boot_completed=1` 再返回。
   ```powershell
   # 正常启动
   .\tools\start-emulator.ps1
   # 内存很紧也要开
   .\tools\start-emulator.ps1 -Force
   # 怀疑显卡驱动时改软件渲染
   .\tools\start-emulator.ps1 -SoftwareGpu
   ```
   > 脚本是 UTF-8 with BOM 保存的，Windows PowerShell 5.1 直接双击 `.ps1` 会因执行策略被拒；用 `.cmd` 或
   > `powershell -ExecutionPolicy Bypass -File tools\start-emulator.ps1`。

## 还没做、但建议做的

1. **开模拟器前关掉 Edge 和 Steam**：这两项加起来约 2.4 GB，关掉后可用内存能回到 3.5 GB 以上，比任何参数调整都有效。
2. **跑一次内存诊断**（因为出现过 `0x4E`）：`mdsched.exe` → 重启检查。若报错，说明内存条有问题，优先换条/关 XMP。
3. **加内存到 32 GB**：16 GB 跑「Android Studio + 模拟器 + 浏览器」本来就在临界点，这是根治。
4. 若冷启动后仍然卡死，把模拟器换成软件渲染再试（`-SoftwareGpu`），排除 GPU 驱动；再把 `-Cores` 降到 2。

## 判断修复是否生效

- 启动后看 `可用内存`（脚本会打印）；低于 800 MB 时系统仍然容易卡。
- 事件日志里 `Kernel-Power 41` / `BugCheck 1001` 不再新增（`Get-WinEvent -FilterHashtable @{LogName='System'; Id=41}`）。
